# 加载失败（Failed to fetch）修复 · 2026-10-23

## 现象
切难度（尤其是「英雄」）、切周、查玩家、开幻痛时，偶发整块变成一行红字「加载失败：Failed to fetch」，只能刷页面。

## 根因
1. 源站 `api.huaxu.app` 偶发卡住/断流：实测 `warzone/current/15` 多次 20s 不返回（curl 000），`/16` 32KB 也要 20s 才收完。浏览器拿不到响应就直接抛 `TypeError: Failed to fetch`，没有 HTTP 状态码。
2. 前端没有任何兜底：`src/api/client.js` 的 `fetchJson` 没有超时、没有重试、没有并发去重；`useWarzone` 一失败就 `setError`，`RankingPanel` 直接 `return <div>加载失败：…</div>`，把已有数据整页替换掉。
3. 错误语义错位：`PlayerPage` 把所有异常都报成「未找到该玩家」，断网也会被说成查无此人；`PpcPage` 则是静默空白。

## 改动
- `src/api/client.js`
  - `requestJson`：单次请求 10s 超时（AbortController），网络错误 / 5xx / 429 指数退避重试 2 次（400/800ms），4xx（除 429）不重试。
  - `fetchJson`：同 URL in-flight 合并（StrictMode 双执行、连点切难度只发一次）；缓存加 48 条上限，按插入顺序淘汰；过期项读取时清理。
  - 新增 `friendlyError(e)`：把 `Failed to fetch` / 超时 / 5xx / 429 翻译成中文文案。
  - `loadPlayer`：404 → 「未找到该玩家」（带 `notFound` 标记）；其余错误原样上抛，由页面报网络问题。
- `src/hooks/useWarzone.js`：请求序号守卫（丢弃过期响应，快速切难度不串台）；失败**保留上一次数据**，只置错误；同一「难度/周」自动重试一次（1.5s 后），避免死循环。
- `src/components/Ranking/RankingPanel.jsx`：去掉整页报错；有旧数据 → 顶部横幅「传奇 (80-120)：网络连接失败，请稍后重试，当前显示的是上一次成功加载的数据 ＋ 重试」；无数据 → 「数据加载失败 + 重试」空态。
- `src/components/PlayerPage.jsx`：区分「网络失败」与「玩家不存在」，网络失败给重试按钮。
- `src/components/PpcPage.jsx`：补错误横幅 + 重试（原来失败是静默空白）。
- `src/components/Ranking/RankingRow.jsx`：差值没变化时不再渲染「0」（原先每行都有个多余的红/灰 0）。
- `src/styles/ranking.css`：新增 `.data-alert / .data-alert-text / .data-alert-btn`。

## 验证（Playwright，强制断网场景）
- `scripts/test-difficulty.mjs`：6 项断言全 PASS（切难度失败不空白、保留旧数据、中文网络文案、重试可恢复、冷启动失败有重试入口、重试后出数据）。
- `scripts/test-pages-errors.mjs`：4 项断言全 PASS（玩家断网报网络错误且有重试、真·不存在仍报「未找到该玩家」、幻痛断网有横幅）。
- 截图：`docs/ui-audit/v2/error-banner.png`（桌面）、`docs/ui-audit/v2/error-banner-mobile.png`（移动，横幅 59px 高，无横向溢出）。

## 仍需注意
源站对某些难度偶尔 20s+ 不返回，前端只能重试与降级展示；若长期如此，建议做服务端缓存/预取（`/api/*` Serverless 层），或与数据源方确认限流策略。
