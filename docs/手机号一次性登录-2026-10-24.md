# 手机号一次性登录（2026-10-24）

## 为什么要改

原来的登录是两步：先「网站账号 + 密码」注册登录，再单独「绑定库街区（手机号 + 验证码）」。用户要先想一个用户名和密码，登录完还得再收一次验证码，才能同步分数。反馈是「登录太麻烦」。

现在：输入手机号 → 滑动验证 → 收一条短信 → 输验证码 → 完成。账号、库街区绑定、云端同步一次搞定。

## 数据安全与历史数据

| 情况 | 登录后拿到的账号 |
| --- | --- |
| 手机号从没登录过 | 自动建号，`player_id = 手机号`，昵称显示 `138****0000` |
| 老用户（用户名 + 密码注册过，且绑定过库街区） | 按云端 `user_data.kuro_phone` 匹配到老账号，直接接管原 `player_id` |
| 手机号账号存在但是空壳，老账号却有分数 | 用老账号（历史数据优先） |

接管意味着：老账号的 `wz_scores`、`ppc_scores`、`follows`、`history`、`bind` 全部照旧，因为云端数据按 `player_id` 存，`player_id` 没有变。老账号的密码登录也仍然可用（折叠入口「老账号密码登录」）。

## 服务端做了什么

新增 action `phone_login`（`api/auth.js`）：

1. 校验手机号 / 验证码格式。
2. **自己调库街区** `sdkLoginForH5`（失败回落到 `sdkLogin`）用手机号 + 验证码换 kuro token —— 验证码由库街区校验，所以手机号归属可信，前端传什么手机号都会被真实校验。
3. 查 / 建账号（见上表），写 `sessions`（7 天）。
4. 顺手把 `kuro_token`、`kuro_phone` 写进 `user_data`，所以「绑定库街区」这一步从此消失，换设备也不用重新绑。

`user_data` 的 `data` 列是 jsonb，反查手机号要用带引号的字面量：`.filter('data', 'eq', JSON.stringify(phone))`。

## 前端改了什么

- `src/api/auth.js`：新增 `loginWithPhone(phone, code)`，成功后写 session、写本地 `kurobbs_token` / `kurobbs_phone`、拉一次云端数据。
- `src/components/MinePage.jsx`
  - `LoginModal` 只剩一套表单（手机号 + 验证码），底部折叠「已有老账号？用密码登录」；已登录时显示状态，可「换个账号登录」。
  - `SetupGuide` 从三步压到两步：手机号登录 → 同步分数。
  - 账号卡未登录时只有一个「手机号登录」按钮；库街区卡未登录时只留一句说明，不再重复摆验证码表单。

## 不需要改数据库

`users` 表沿用 `player_id` 作主键，手机号账号的 `player_id` 就是手机号（11 位数字）。以后如果要做「换手机号」「一个账号绑多个手机号」，再加 `users.phone` 列和索引即可，届时把 `player_id = 手机号` 的写法换掉就行。
