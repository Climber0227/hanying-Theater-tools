# 服务端缓存代理（api/huaxu.js）

## 要解决的问题

榜单数据一直是**浏览器直连** `https://api.huaxu.app`，你的服务端完全不参与。所以：

- 你之前遇到的「切英雄卡 20s / Failed to fetch」，前端只能靠超时重试兜底，救不回来；
- 每个用户、每次切难度都要自己去源站要一份 200KB 的数据，源站压力和你无关但也帮不上忙；
- 源站虽然挂了 Cloudflare（`max-age=60`），但缓存过期那一下回源慢，所有用户一起等。

现在加一层自己的缓存代理：请求先进 Vercel CDN，命中就直接返回，不执行函数、不回源。

## 链路

```
改之前： 浏览器 ──直连──> api.huaxu.app (Cloudflare) ──> 上游
改之后： 浏览器 ──同源──> /api/huaxu ──> Vercel CDN
                          ├─ 命中（<60s）：直接返回，函数不执行
                          └─ 未命中：函数回源 → 写快照 → 带缓存头返回
                                        └─ 源站超时/5xx → 返回上一份快照（stale）
```

## 实现

### `api/huaxu.js`（新增，无第三方依赖）

`GET /api/huaxu?path=/servers/cn/warzone/current/16[&q=ranking=true][&nocache=1]`

- **白名单**（防止变成任意 URL 代理），只放行真实用到的 5 类路径：

  | 路径 | CDN 缓存 | 说明 |
  | --- | --- | --- |
  | `/servers/cn/warzone/{current\|周}/1-16` | 60s | 榜单，主要流量 |
  | `/servers/cn/ppc/{current\|周}/{level}` | 60s | 幻痛囚笼 |
  | `/servers/cn/players/{id}` | 120s | 玩家资料 |
  | `/servers/cn/players/{id}/warzone` | 300s | 历届战绩（300KB，最值得缓存） |
  | `/servers/cn/players/{id}/characters/{charId}` | 3600s | 角色详情，基本不变 |

  路径里出现 `..`、`//`、超长、非法难度都会被 400 拒掉。

- **缓存头**（三条一起给，兼容不同 CDN）：

  ```
  Cache-Control: public, s-maxage=60, stale-while-revalidate=600, stale-if-error=86400
  CDN-Cache-Control: 同上
  Vercel-CDN-Cache-Control: 同上
  ```

  - `s-maxage` 决定 CDN 存多久；
  - `stale-while-revalidate` 让过期后**先给旧数据**、后台再刷 —— 用户永远不用等那 20s；
  - `stale-if-error` 让源站挂掉时 CDN 继续发旧的，不会把 502 抛给用户。

- **进程内快照兜底**：每次成功响应留一份（最多 60 个、30 分钟），源站 5xx/超时/断流时直接返回它，响应头 `X-Data-State: stale`。冷启动第一次就打到坏源站时才会返回 504。

- **超时与重试**：单次 9s 超时（源站偶发 20s+，等它没意义）；5xx/429 再试一次；4xx 原样透传并标 `no-store`（玩家的「查无此人」逻辑不受影响）。

- **nocache**：手动刷新时前端带 `nocache=1`，代理返回 `no-store`，保证点刷新真的会回源。

- 只用标准 Node `req`/`res` API，不依赖 Vercel 的 Express 风格 helper，本地也能直接跑起来测。

### 前端改动

- `src/api/config.js` 新增 `apiUrl(path, query)` / `apiUrlNoCache(path, query)`，并在运行时判断：
  - 线上（非 localhost）→ `/api/huaxu?...`
  - `vite dev` / Electron（`file://`）→ 仍直连源站（本地没有 Serverless 函数）
  - 测试可通过 `window.__HUAXU_FORCE_PROXY__` 强制走代理
- 7 个调用点全部改走 `apiUrl`：榜单、幻痛、玩家资料、历届战绩、角色详情、我的页两处。
- `fetchJson` 新增 `networkUrl` 参数：**缓存 key 保持不变，只有这一次请求换个地址**。这样手动刷新拿到的数据会写回原来的缓存 key，下次切回来是新的。
- 走 `/api/*` 的请求带 `credentials: 'omit'`（无凭据的响应 CDN 才会缓存）。


结果：

## 部署后怎么确认 CDN 真的在缓存

我没有你 Vercel 的登录态，没法替你部署。部署后跑这两条：

```bash
curl -sI "https://jiatenghui.icu/api/huaxu?path=%2Fservers%2Fcn%2Fwarzone%2Fcurrent%2F16" | grep -i -E "cache-control|x-vercel-cache|x-data-state"
curl -sI "https://jiatenghui.icu/api/huaxu?path=%2Fservers%2Fcn%2Fwarzone%2Fcurrent%2F16" | grep -i x-vercel-cache
```

- 第一次应当是 `x-vercel-cache: MISS` + `x-data-state: fresh`；
- 60s 内再请求一次，应当是 `x-vercel-cache: HIT`（且没有 `x-proxy-ms`，因为函数没执行）。

## 成本

- **不花 Supabase 任何额度**：这条链路完全不碰数据库。
- Vercel Hobby：Fast Data Transfer 100GB/月。榜单 JSON 202KB，gzip 传输约 45KB；按每天 3000 次取数算 ≈ 135MB/天 ≈ **4GB/月**，占 4%。
- 函数调用：只有缓存未命中才执行，一天几十次；Hobby 的额度是百万级，可以忽略。

## 风险与回滚

- **Vercel CDN 对函数响应的缓存有前提**：响应不能带 `Set-Cookie`、状态码 200、方法 GET。本函数都满足；但如果部署后发现始终 `MISS`，说明你的计划/配置禁用了函数响应缓存，此时快照兜底仍然生效（功能不受影响，只是没省掉回源）。
- 缓存窗口内数据最多旧 60s（与源站自己的 `max-age=60` 一致，不会比现在更旧）。
- **回滚**：`src/api/config.js` 里把 `USE_API_PROXY` 改成 `false` 并重新部署即可，前端会恢复直连源站，`api/huaxu.js` 留着不碍事。

## 部署后实测（2026-10-23）：上游 Cloudflare 挡住了数据中心 IP

部署（commit `c4ee732` → `9b584a9` → `67dbf88`）后实测，结论和预期相反，必须记录：

```
$ curl -sD - -o /dev/null "https://jiatenghui.icu/api/huaxu?path=%2Fservers%2Fcn%2Fwarzone%2Fcurrent%2F16"
HTTP/1.1 403 Forbidden
Content-Type: text/html; charset=UTF-8     <- 上游返回的是 Cloudflare 验证页
Content-Length: 5821
```

- 函数本身是通的（`HEAD` 会返回我们自己写的 405），但它在 `iad1` 数据中心 IP 上请求 `api.huaxu.app` 时，
  被 Cloudflare 判定为机器人，返回「Just a moment...」验证页（`cdn-cgi/challenge-platform`）。
- 空壳 Vercel 的出口 IP 无法通过 JS 挑战，所以**服务端代理这条路在当前上游策略下走不通**，
  除非上游给白名单/API key，或者换一个不受挑战的数据源。
- 更糟的是第一版把验证页当 4xx 原样透传给了浏览器（`response.json()` 直接抛错），
  线上短暂出现「榜单加载失败」。

### 因此加了自动降级（这是现在线上的状态）

| 层 | 行为 |
| --- | --- |
| `api/huaxu.js` | 认出 HTML/验证页 → `502 {"error":"upstream_blocked"}` + `X-Proxy-Usable: 0` + `no-store`，绝不透传验证页 |
| `src/api/client.js` | 收到 502/HTML 时把「代理不可用」写进 localStorage（12 小时），立刻改用直连源站并复用同一缓存 key |
| 之后的请求 | 12 小时内直接连源站，一个多余请求都不发 |

实测（真实浏览器，线上）：

- 首次访问：`/api/huaxu` 3 次 502（45 字节，几十毫秒）→ 自动直连 → 榜单 8 行正常渲染，无控制台报错；
- 同上下文刷新：**0 次代理请求**，546ms 出首行；
- 19 张图全部 webp，0 失败。

### 结论

- 现在线上**功能正常**，但拿到的是「直连 + 客户端缓存」，不是 CDN 缓存；
- 想要服务端缓存，只有三条路：① 上游放行你的 Vercel IP（找 huaxu.app 维护者加白名单/给 key）；
  ② 换一个不受 Cloudflare 挑战的数据源；③ 用你自己的域名/服务器做反向代理（同样会被挑战，除非有白名单）。
- 代理代码保留着：一旦上游放行，前端会在 12 小时内自动恢复走 `/api/huaxu`，无需改代码。
