# 含英牌战区数据 · 全站优化方案

> 版本：2026-10-23　｜　范围：整体 UI → 性能 → UI 布局
> 配套材料：现状截图 `docs/ui-audit/current/`，改版设计稿 `docs/ui-audit/mockup/home-v2.html`

---

## 0. 一句话结论

这个站的功能和结构是清楚的，问题出在**层次感**：底色是一整块从白到黑的斜向渐变，卡片是半透明的白，所有内容都「漂」在中间。于是对比度随滚动位置变化，主标题在深色带上直接消失；标题、正文、次要信息共用 11–14px 的字号，数字不突出；首屏又被导航、三区卡、筛选说明、六个下拉框层层占满。

所以顺序不是「先换配色」，而是先立地基：**表面层级 → 字阶 → 组件规范 → 信息密度**。地基立住之后，性能优化和逐页布局才不会再返工。

## 1. 现状诊断

### 1.1 视觉层：三个根因

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | 全局背景是 `linear-gradient(135deg,#fff 0%,#f5f5f7 14%,#4d4d4d 42%,#333 58%,#1a1a1a 78%,#000 100%)` 且 `background-attachment: fixed` | `src/styles/theme.css:35-44`；`desktop-player-empty.png`、`desktop-ppc.png` | 页面标题「玩家查询」「幻痛囚笼」落在深色带上，几乎不可读；同一块面板在不同滚动位置颜色不同 |
| 2 | 榜单面板用 `rgba(255,255,255,0.55)` + `blur(24px)` 叠在渐变上 | `src/styles/ranking.css:2-11` | 面板发灰、发浑，白色文字块和背景糊在一起；同时 `backdrop-filter` 是滚动掉帧的主因之一 |
| 3 | 没有字阶：正文 11/12/13/14px 混用，字重 500/600/700 随机；数字没有统一 `tabular-nums` | `src/styles/pages.css`、`ranking.css` 全文 | 分数、排名、战力、说明文字权重接近，眼睛不知道先看哪 |
| 4 | 组件三套皮：黑胶囊按钮、描边胶囊按钮、纯文字按钮；圆角 12/14/20/24 四种；阴影 4 档 | `app.css`、`ranking.css`、`pages.css` | 页面像多个模板拼起来 |
| 5 | 状态设计缺失：空状态是灰底一行灰字，加载中是整块空白，图片没加载时是「文字墙」 | `desktop-ppc.png`、`desktop-player-loaded.png`、`modal-trend.png` | 用户分不清「没数据」「在加载」「加载失败」 |
| 6 | 广告 340px、1.34MB、`ad-flash` 无限缩放+发光动画，压住前三名；右下反馈胶囊在手机上压住总分 | `src/styles/app.css:202-213`、`desktop-warzone.png`、`mobile-warzone-noad.png` | 首屏最贵的位置被广告占掉，且无限动画持续耗电 |

补充：品质标签用的是 iOS 系统色（`src/styles/pages.css:283-288`），和全站黑白灰没有关系，是目前唯一的彩色来源，反而显得杂。

### 1.2 性能层：瓶颈不在 JS

构建产物实测（`dist-web/assets`，gzip 后）：

| 资源 | 原始 | gzip |
|---|---|---|
| `index-*.js` | 233 KB | 72.8 KB |
| `index-*.css` | 81 KB | 13.7 KB |
| `BracketModal-*.js`（recharts） | 358 KB | 102.6 KB |
| `ChangelogPage-*.js` | 133 KB | 44.3 KB |
| `favicon.ico` | 119 KB | — |

**JS/CSS 首屏只有 ~87 KB gzip，不算问题。真正的瓶颈是图片和请求数：**

| 问题 | 实测/文档数据 | 位置 |
|---|---|---|
| 角色头像 1024×1024 PNG，单张约 1 MB | 玩家页 88 图 ≈ 55.1 MB，首页 26 图 ≈ 9.1 MB | `src/api/config.js:10-13` 统一拼 `.png` |
| 历史战绩串行探测 | 20 周 = 17.6 s / 27 个请求；而 `/players/{id}/warzone` 一次返回约 100 周 | `src/components/Modals/HistoryModal.jsx:120-167` |
| 曲线采样写 localStorage | 200 条 × 100 人 ≈ 3 MB，同步 JSON.parse | `src/api/storage.js:11-44` |
| 客户端缓存只增不减 | `Map` 无上限、无 inflight 去重 | `src/api/client.js:5-19` |
| 首页全量图片无 lazy | `RankingRow` 每行约 20 张图（头像+框+3角色×2图×3区） | `src/components/Ranking/RankingRow.jsx:46,50,115,172` |
| 首屏无 preconnect | `index.html` 仅 13 行 | — |

好消息：资源站同路径已有 WebP——`rolehead...webp` 实测 148 KB（PNG ≈ 1.03 MB），头像这一项就能省 85%。

### 1.3 布局 / 信息架构

- **首页**：导航(49) → 三区卡 → 控制行 → 排行榜标题 → 一整段筛选说明 → 搜索 → 三个按钮 → 每区 3 个下拉框 + 全SSS/全SSS+ → 表头。真正数据被压在 7 层 chrome 之后。
- **手机首页**：`scrollH 1357`，统计行 70px + 5 tab + 三张战区卡纵排（各 ~95px），首行数据落在约 **1600px**（视口 1688）——打开就是「一屏控制面板」。
- **玩家页**：搜索框和标题居中、查询历史在资料卡之前，查完要往回滚；85 张角色卡固定 8 列，图标没加载时是一堵文字墙。
- **我的页**：「2 我的战区」出现在「1 账号·库街区」之前，编号顺序错乱；三块「暂无数据」占据大半屏；长段「注意：…」说明文字直接铺开。
- **幻痛页**：标题不可见，加载时整块空白，没有骨架屏。
- **弹窗**：`分数分布` 的 X 轴标签 45° 旋转且被容器裁掉；`趋势` 弹窗两个大空框只写一行小字。

## 2. 改版方向

### 2.1 四条原则

1. **表面分层，而不是背景装饰**：页面底色是安静的中性灰，内容全部落在实色白卡上；层级靠「白卡 + 1px 细边 + 极轻阴影」，不靠渐变和毛玻璃。
2. **数据优先**：任何页面，第一屏必须能看到数据；控制项收进面板内或抽屉里。
3. **一套刻度**：字号、间距、圆角、阴影、动效全部走令牌，不再出现 12/14/20/24 混用。
4. **状态即设计**：加载 = 骨架屏（形状和真实内容一致），空 = 图标 + 一句解释 + 一个动作，错误 = 可重试。

### 2.2 两个视觉方向（都已出稿，可直接看）

**方向 A · 浅色数据台（推荐）**

![](./ui-audit/mockup/home-light-desktop.png)

- 底 `#ECEFF3`，卡片纯白，1px `#E4E7EC` 细边；只在弹窗/悬浮操作上用投影。
- 主色仍是墨黑（`#14171C`），金色只留给冠军和「同阶最高」，红/绿只表达分数差。
- 优点：密集数据可读性最好、和现有品牌调性连续、改造风险最低、暗色适配手机屏幕时也不会「一片黑」。

**方向 B · 深空（游戏感更强）**

![](./ui-audit/mockup/home-dark-desktop.png)

- 底 `#0A0B0D`，卡片 `#121417`，靠 1px `#23272E` 勾边而不是阴影。
- 优点：更贴战双的科幻气质，榜单金色/红色在暗底上更跳。
- 代价：空状态、图表、第三方广告图都要重新调；图片透明边缘、白底截图容易露馅；整体工作量比 A 多约 30%。

**移动端（两套方向通用）**

| 浅色 | 深色 |
|---|---|
| ![](./ui-audit/mockup/home-light-mobile.png) | ![](./ui-audit/mockup/home-dark-mobile.png) |

移动端做了三件关键的事：去掉纵向三区卡（区域名改为行内标签）、筛选芯片单行横滑、行内隐藏角色 chip（点行看详情）。首行数据从 ~1600px 提到 ~420px。

> 设计稿是静态 HTML，可直接在浏览器打开对比：`docs/ui-audit/mockup/home-v2.html`，加 `?theme=dark` 切深色。

### 2.3 设计令牌（草案）

```css
/* 颜色 —— 浅色 */
--bg:#eceff3;  --card:#ffffff;  --card-2:#f6f7f9;  --card-3:#eef0f3;
--line:#e4e7ec; --line-strong:#d5d9e0;
--ink:#14171c;  --ink-2:#545b66;  --ink-3:#8a919d;  --ink-4:#b0b6c0;
--brand:#14171c; --on-brand:#ffffff;
--gold:#b07a12; --gold-soft:#fdf5e3;
--red:#cf3d3d;  --red-soft:#fdf0ef;
--green:#22845f; --green-soft:#ecf7f1;

/* 字号 —— 只有 6 档 */
--fs-11:11px;  /* 辅助/图表轴 */
--fs-12:12px;  /* 元信息 */
--fs-13:13px;  /* 正文/表格 */
--fs-15:15px;  /* 行标题/强调数字 */
--fs-19:19px;  /* 面板标题 */
--fs-26:26px;  /* 页面标题 */

/* 间距 —— 4 的倍数 */
--s-1:4px; --s-2:8px; --s-3:12px; --s-4:16px; --s-5:24px; --s-6:32px;

/* 圆角 —— 只有 3 档 */
--r-sm:8px;   /* 按钮/输入 */
--r-md:12px;  /* 小卡/导航 */
--r-lg:16px;  /* 面板/大卡 */

/* 动效 */
--ease:cubic-bezier(.16,1,.3,1); --dur:180ms;
```

### 2.4 组件规范

| 组件 | 规范 |
|---|---|
| 主按钮 | 墨黑实心、8px 圆角、高 34px、13px/600；一屏最多 1 个 |
| 次按钮 | 白底 1px 边、hover 变 `--card-2`；不再用胶囊描边 |
| 幽灵按钮 | 无边框，用于「刷新/更多/视图切换」 |
| 输入 | 高 34px、`--card-2` 底、聚焦时白底 + 墨色 1px 边（去掉外发光） |
| 标签 | 11px、5px 圆角、`--card-3` 底；`TOP 100` 这类用描边款 |
| 卡片 | 白底 + 1px 边 + `0 1px 2px rgba(16,24,40,.04)`；hover 只加深边框 |
| 数字 | 全局 `font-variant-numeric: tabular-nums`，分数用 15px/650 |
| 空状态 | 40px 线性图标 + 一句话 + 一个主按钮，高度不超过 160px |
| 骨架屏 | 和真实行同高同列宽的灰块 + 1.6s 呼吸，不用 spinner |

## 4. 阶段二：性能

目标：首屏从「等图」变成「先看到数」。按收益排序。

### 4.1 图片链路（最大头，预计首屏省 8 MB+）

1. `getImageUrl()` 改为输出 `.webp`，并用 `<picture>` 或 `onError` 回退 `.png`（资源站两种格式都存在）。
2. 所有 `<img>` 补 `width/height` 或 `aspect-ratio`，消灭 CLS。
3. 首屏图 `fetchpriority="high"`，其余 `loading="lazy" decoding="async"`。
4. `RankingRow` 每行从约 20 张图降到 9 张：保留 14px 角色头像，去掉重复的辅助机/小方块图标（信息移到「分析」弹窗）。
5. 玩家页 85 张角色卡：`content-visibility: auto` + 原生 lazy + 骨架占位。
6. 广告图 1.37 MB → 压缩成 WebP ≤ 150 KB。

预计：首页首屏图片 9.1 MB → ~0.6 MB；玩家页 55.1 MB → ~3 MB（只加载视口内）。

### 4.2 历史战绩：27 个请求 → 1 个

- `loadPlayerHistory` 直接取 `/players/{playerId}/warzone`（一次返回约 100 周），本地按周/位段筛选。
- 删除 `HistoryModal.jsx:120-167` 的串行探测循环与 `sleep(60)`。
- 保留 `huaxu_roster_*` 6h 缓存，改为 stale-while-revalidate（先出旧数据再刷新）。

预计：17.6 s → 1.5 s 内。

### 4.3 曲线采样瘦身

- 只存「本人」曲线，不再把整榜 100 人写进 localStorage；上限 60 点。
- 存储从 localStorage 换 IndexedDB（异步、容量大）。
- 采样时机从「每次加载 + 30 分钟定时器」改为「数据变化时 + 页面可见时」，去掉 `useWarzone.js:39-98` 的 `setInterval`。

预计：首次解析 3 MB JSON 的 300–800 ms 卡顿消失。

### 4.4 客户端缓存

- `client.js`：`Map` 加 LRU（上限 20 条）+ `inflight` 去重，切页/切周不重复请求。
- 榜单快照落 localStorage（5 分钟），刷新页面先渲染旧快照。

### 4.5 构建与首屏

- `index.html` 加 `preconnect` 到 `assets.huaxu.app` 与 API 域名。
- 移除 recharts：只有 `BracketModal.jsx` 用，358 KB（102 KB gzip）。`CurveModal` 已是手写 SVG，分数分布照同样方式重写，顺带修 X 轴标签被裁的问题。
- 保留现有路由级懒加载；`ChangelogPage` 的 133 KB 数据改为 `fetch` 静态 JSON 或按年份拆。

### 4.6 渲染与动画

- 删除所有 `infinite` 动画（广告发光、卡片呼吸）。
- `backdrop-filter` 只留导航与弹窗遮罩。
- 导航「建站 172 天 18 时…」的每秒 `setState` 收进独立小组件，避免整条导航重渲染。
- 行组件 `React.memo` + 稳定回调（虚拟滚动已有）。

### 4.7 接口与定时任务（可选，按需）

- 首页头部信息改用轻量接口 `/servers/cn/warzone/current`（2.5 KB）与 `/ppc/current`（2.3 KB）。
- cron 从 768 次/天降到 48–96 次/天。

**验收**：4G 模拟下 LCP < 2.5 s、CLS < 0.05、首屏传输 < 1.2 MB、首屏请求 < 40、历史战绩 < 2 s。

## 5. 阶段三：UI 布局（信息架构 + 响应式）

### 5.1 首页（战区数据）

- 页头一行讲清「第几周 / 时间范围 / 参与人数 / 更新时间」，难度切换做成 3 段控件。
- 三区卡升级为「有信息的卡」：区名 + 机制 + 本周榜首 + 该区最高分 + 参与人数 + 详情入口。
- 排行榜：周选择并入面板头；`筛选` 收进一个按钮 + 激活芯片；「角色阶级筛选」那段说明改成 `?` 气泡。
- 表头每区只保留一个漏斗图标（有筛选时高亮 + 计数），不再平铺 6 个链接。
- 行：分数主行 + 3 个角色 chip 次行；`分析/趋势` 改为 hover 浮出的胶囊（移动端常驻图标）。
- 表头 sticky；`总分` 列固定右侧。
- 手机：表格转卡片（每区一行「区名 分数 差值」），筛选进底部抽屉。

### 5.2 玩家查询

- 两栏：左侧 300px 粘性资料卡（头像/等级/公会/点赞/关注/历史战绩），右侧角色列表。
- 搜索框移到页头，查询历史改成横向 chip 行（最多 6 个 + 清空），不再占一张大卡。
- 角色网格 `repeat(auto-fill, minmax(150px, 1fr))`，卡片 = 头像 + 名字 + 等级 + 品质；缺图时显示首字占位。
- 角色列表默认折叠到「常用 12 个 + 展开全部」，减少首屏高度。

### 5.3 我的

- 顺序修正：`1 使用引导 → 2 账号·库街区 → 3 我的战区 → 4 历史记录`。
- 空状态全部换成「图标 + 一句解释 + 去同步」的可点击卡。
- 「注意：历史记录自…」等长说明收进 `<details>` 或标题旁的 `?`。
- 今日/本周两张趋势图并排，空数据时降到 120px 高。

### 5.4 幻痛囚笼

- 标题 + 难度/周控件收进页头一行；榜单加载用 8 行骨架，不再整块空白。

### 5.5 更新日志

- 时间线左对齐日期（sticky），每条默认折叠到 3 行，长条目「展开」。

### 5.6 弹窗

- 统一 `Modal` 外壳：标题区（标题 + 副标题 + 关闭）、可滚动内容区（`max-height: 85vh`）、底部操作区。
- 图表统一手写 SVG：轴标签水平、超长省略、tooltip 跟随。
- 空数据不再给大白框，直接 EmptyState。

### 5.7 响应式断点

`1280 / 1024 / 860 / 640 / 420`；规则：1024 以下表格列收窄，860 以下三区卡改单列横滑，640 以下表格转卡片、导航 5 等分、隐藏非核心统计。
