# 性能优化（2026-10-23）

目标：在不动功能、不动广告画面、不影响现有视觉的前提下，把首屏请求量和等待时间降下来。
顺序：整体 UI（已完成）→ **性能（本文）** → UI 布局。

## 一、改了什么

### 1. 图片：PNG → WebP（最大头）

资源站（`assets.huaxu.app`）同一路径下同时有 `.png` 和 `.webp`，实测体积约为 png 的 1/7：

| 资源 | PNG | WebP |
| --- | --- | --- |
| `rolecharacter/rolehead…`（角色头像 1024×1024） | ~1.03 MB | 148 KB |
| `roleplayersp/rolehead…`（玩家立绘） | ~82 KB | 12.6 KB |
| `roleplayersp/headframe…`（头像框） | ~65 KB | 14 KB |
| `…/pet…`（辅助机） | ~51 KB | 13 KB |

- `src/api/config.js`：`getImageUrl(path)` 统一返回 `.webp`，另导出 `getImageUrlPng(path)`。
- 新增 `src/api/imageFallback.js`：document 上以 capture 监听 `error`，某张 `.webp` 真的取不到时换成同路径 `.png`，只换一次（防止死循环）。在 `src/main.jsx` 里 `installImageFallback()`。

### 2. 角色图标改成「进视口才加载」

玩家页一次渲染 85 个角色卡，每个图标是 1024×1024 原图缩到 48px 显示。原生 `loading="lazy"` 在 Chromium 里预取距离是 1250px，而整页只有约 1000px 高 → 等于全部立刻加载。

新增 `src/components/LazyImage.jsx`（IntersectionObserver，`rootMargin="300px"`，未进视口时用 1×1 透明占位，保留 48×48 尺寸防抖动），用在角色图标与查询历史头像上。

实测（本地预览 + mock 接口）：玩家页图片请求 **87 → 37**，滚动时再按需加载。

### 3. 广告图与 favicon

- 广告图：`974×868` PNG 1.34 MB → 680 宽 WebP 138 KB（显示宽度 340px，2x 屏正好）。原图移到 `docs/legacy/ad-warzone-original.png`，不再随部署发布；`AdFloat.jsx` 只改 `src`，画面、位置、动画、拖拽一律没动。
- `favicon.ico`：256×256 单尺寸 119 KB → 16/32/48 三尺寸 10.6 KB。

### 4. 历史战绩：27 个请求 → 1 个

原来 `HistoryModal` 是「逐周 × 最多 16 个段位」串行探测，每查一次 sleep 60ms、每周再 sleep 150ms（线上实测 20 周 ≈ 27 个请求 / 17.6s）。

改为调用已有的 `src/api/history.js#loadPlayerHistory()`：一次 `GET /servers/cn/players/{id}/warzone` 拿回该玩家约 100 周的上榜记录（约 316 KB，gzip 后很小），在内存里按周范围过滤。`normalizeWeek()` 补了 `zoneMeta`（区名/属性）供弹窗渲染。

实测（mock）：**17.6s / 27 请求 → 0.3s / 1 请求**。

### 5. 登录后的云端同步

`src/api/auth.js`：

- `init()` 做单例（多个组件各调一次 `init()`，原来会各拉一遍云端）；顺带修掉「init 拉一次 + `_pullFromCloud()` 又拉一次同一个接口」的重复 GET。
- `_pushToCloud()` 由 6 条串行 PUT 改为并发。
- 会话失效（`_clearLocal`）时重置单例，允许后续重新拉取。

### 6. 网络预连接

`index.html` 加 `preconnect` / `dns-prefetch`（`assets.huaxu.app`、`api.huaxu.app`），省掉首屏的 DNS + TLS 往返。

### 7. 试过但回滚的：手动拆 chunk

`manualChunks` 把 react / vendor / recharts 拆开，首次加载反而从 240 KB（gzip 76）涨到 361 KB（gzip 115），因为分包开销 + 共享模块重复。已回滚，保留默认单 chunk。

## 二、before / after

测量方式：`vite preview` 起本地生产构建 + Playwright 跑 `scripts/perf-audit.mjs`，接口用 `MOCK=1` 回放真实响应（源站偶发 20s 不返回，不 mock 量不到数据），基线用 `git worktree` 检出改动前的提交构建。

| 页面 | 改动前 | 改动后 |
| --- | --- | --- |
| 首页 | 1546 KB · 7 请求 | **238 KB** · 13 请求 |
| 玩家查询 | 1555 KB · 9 请求 | **247 KB** · 11 请求 |
| 幻痛囚笼 | 1548 KB · 8 请求 | **241 KB** · 8 请求 |
| 历史战绩（打开弹窗查 20 周） | 46 请求（27 个是接口）· 60s 超时未出结果 | **10 请求（3 个是接口）· 0.3s · 19 行** |

首页 1546 → 238 KB，降幅 84.6%。其中广告图 1.34 MB + favicon 117 KB 就占了 1.45 MB，剩下是 JS/CSS。

> 注：表里「KB」是首屏可见的静态资源传输量。接口响应是跨域不透明响应，浏览器不暴露大小，所以不计入。

## 三、验证

```bash
npm run build
npx vite preview --port 4173 --host 127.0.0.1
MOCK=1 BASE_URL=http://127.0.0.1:4173 node scripts/perf-audit.mjs after
node scripts/shot-perf.mjs        # 出 docs/ui-audit/v2/perf-*.png
```

- 五个页面无控制台报错、无 pageerror（`scripts/_smoke.mjs` 临时脚本验证后已删）。
- 图片 `src` 全部为 `.webp`，未出现 png 兜底（说明资源站 webp 齐全）。
- 历史战绩弹窗 19 周 / 57 个区正常渲染，区名与分数正确。

## 四、仍需注意

1. **本机到 `assets.huaxu.app` 极慢**：大量图片请求 25s 不返回（不是 404，重试就 200）。所以本次截图里部分头像显示为首字占位，这是网络环境问题，不是代码问题。真实用户环境下 webp 会让这批图片快 7 倍。
2. **真正的瓶颈在服务端**：`/servers/cn/warzone/current/{难度}` 某些难度会 20s+ 不返回，客户端只能超时兜底。下一步最有效的是在 Vercel 侧给这个接口加缓存（`s-maxage`），而不是继续抠前端。
3. 角色图标仍是 1024×1024 原图（CDN 上没有缩略图），85 张 ≈ 5.5 MB。如果要再降，需要在自家域名做一层 `?w=96` 的图片缩放服务。
4. `src/hooks/useWarzone.js` 里 30 分钟的自动刷新 `setInterval` 还在；页面不可见时也可以跳过。
