# 手机端适配设计文档

> 状态：设计完成，待实现
> 日期：2026-08-08
> 目标：React 版（refactor-react）在 ≤560px 视口下获得完整的移动端体验

---

## 一、现状诊断（调研结论）

| 模块 | 375px 下的问题 |
|---|---|
| 排行榜表格 | 总宽 1320px（80 排名 + 220 玩家 + 268×3 三区 + 160 总分 + 56 重置），必溢出 |
| 弹窗 | `max-width: 900px`，窄屏未处理，内部表格（历史战绩/阵容）溢出 |
| 导航 | 一长串建站统计 + 5 个 tab，560px 断点仅让 stats 换行，挤压 |
| hover 交互 | 分析/趋势按钮、操作区靠 `:hover` 浮现 → **手机上不可见** |
| 页面 grid | `auto-fill minmax` 会自动单列 ✅（角色卡 160 / boss 卡 200 / 关注 240） |
| 现有 @media | 仅 4 处：nav-stats(860/560)、history-zones(480)、tl(640) |

main 版教训：线上 main 用的是 `viewport width=1200` 固定视口（桌面缩略图），即被吐槽的版本，**不要沿用**。

## 二、排版方案

统一断点：`@media (max-width: 560px)` 为主（375px 目标设备），个别组件用 480/700。

### 1. 导航（app.css）
- 导航改为**两行**：第一行 `.nav-stats`（小字，建站/访问/数据来源），第二行 `.nav-btns` 5 个 tab **等宽均分**（`flex: 1`，字号 13px，padding 缩紧）
- 560px 断点：`.nav` 允许 wrap 或改 `flex-direction: column`

### 2. 排行榜（核心，ranking.css + VirtualRankingTable.jsx）
**列宽压缩（JS 联动）**——列宽常量在 `VirtualRankingTable.jsx` 是 JS 常量，需用 `window.matchMedia('(max-width: 700px)')` 动态切换：

| 列 | 桌面 | 手机 |
|---|---|---|
| COL_RANK | 80 | 52 |
| COL_PLAYER | 220 | 150 |
| COL_ZONE | 268 | 150 |
| COL_TOTAL | 160 | 110 |
| COL_RESET | 56 | 0（隐藏） |
| 表格总宽 | 1320 | ~762（手指横滚） |
| ROW_HEIGHT | 152 | 132 |

- `VirtualRankingTable` 加 `isMobile` state（matchMedia + change 监听），列宽/行高/tableWidth 联动；CSS 同断点同步覆盖列样式
- 行内压缩（RankingRow 手机模式）：
  - 隐藏 `cub-icon`、`zone-team-compare`（同阶级阵容比较）、`guild-name`
  - 头像缩小、`char-name-sm` 字号 11px、`char-bp` 隐藏
  - 三区分数 `formatScoreCompact`（紧凑显示）
- **操作按钮常显**：`.ranking-row:hover .zone-actions` → 手机断点下 `.zone-actions { opacity: 1 }` 常显，按钮缩小（分析/趋势各 ~34px 高）
- 控制区（RankingControls）：`ranking-head` 改纵向堆叠，难度/周下拉 `flex: 1` 撑满两列，`date-range` 单独一行；`ranking-meta` 小字换行
- 阶级筛选（RankingHeader）：3 个下拉 + 快速按钮允许换行，字号 12px；表头列宽与行同步压缩

### 3. 弹窗（modals.css + Modal.jsx）
- 560px 断点：`.modal-content` 宽度 `calc(100vw - 12px)`，圆角 12px，`max-height: 90vh` + overflow-y auto；关闭按钮 36×36（触控）
- 弹窗内表格（`.score-table`、阵容排行表、TeamModal 列表）：外层包 `overflow-x: auto` 容器（CSS 加 `.table-scroll` 类或直接对 table 容器设 overflow）
- 历史战绩三区：已有 480px 断点 1 列 ✅

### 4. 玩家查询页（pages.css）
- 搜索框 + 按钮：`flex: 1` 布局已 OK，按钮加 min-height 44px
- 角色卡 `minmax(160px, 1fr)` → 375px 天然 2 列 ✅ 无需改
- 关注/历史列表项：字号 12px，头像 32px
- 玩家信息头（头像/名字/操作按钮）：操作按钮换行

### 5. 幻痛囚笼（pages.css / PpcPage 相关）
- boss 卡 `minmax(200px, 1fr)` → 375px 单列太宽，手机断点改 `minmax(150px, 1fr)` 两列
- 榜单表格横滚容器

### 6. 我的页（pages.css）
- 表单（绑定 ID/登录）：input + button 纵向堆叠，按钮全宽
- 分数录入三区行：纵向堆叠或缩小
- `score-history` 表格横滚

### 7. 广告与反馈（app.css）
- `.ad-float` 宽 340px → 手机 `width: min(340px, 88vw)`
- `.corner-feedback` 字号 10px，避免遮挡内容

### 8. hover 全面检查
- `.zone-sa-btn`、`.bracket-btn`、`.clear-btn` 等所有 `:hover` 浮现/变色的元素，手机端确保**默认可见**（opacity 常显）
- 悬浮按钮可加 `:active` 反馈

## 三、技术要点

1. **列宽常量联动**：`VirtualRankingTable.jsx` 的 `COL_*` / `ROW_HEIGHT` 改为函数或 `isMobile` 分支；CSS 用相同断点覆盖。**两处必须一致**，否则表头/行错位
2. **matchMedia 监听**：`useEffect` + `mql.addEventListener('change', ...)`，旋转/横竖屏切换时更新
3. **虚拟滚动**：`rowHeight` 变化会由 List 的 prop 自动适配，但需触发 ResizeObserver 的 wrapHeight 更新（现有机制已监听）
4. 触控目标：主要按钮（查询/分析/趋势/关闭/筛选）高度 ≥40px
5. 验证手段：Playwright 375px 视口全页面回归——`document.documentElement.scrollWidth <= innerWidth`（无横向溢出，排行榜表格容器除外）

## 四、实现顺序

1. 全局 + 导航（app.css / theme.css）
2. 排行榜（VirtualRankingTable 列宽联动 + ranking.css 断点 + RankingRow 手机渲染）
3. 弹窗全屏化 + 内部表格横滚（modals.css）
4. 玩家查询 / PPC / 我的页
5. 广告、反馈、hover 常显
6. Playwright 375px 回归（每页无溢出 + 交互可点）
