# 手机端适配设计文档

> 状态：设计完成，待实现
> 日期：2026-08-08
> 目标：React 版（refactor-react）在 ≤560px 视口下获得完整的移动端体验

---

## 一、现状诊断（调研结论）

| 模块 | 375px 下的问题 |
|---|---|
| 排行榜表格 | 总宽 1320px（80 排名 + 220 玩家 + 268×3 三区 + 160 总分 + 56 重置），必溢出 |
| 弹窗 | `max-width: 900px`，窄屏未处理，内部表格（历史战绩/阵容）溢出 |
| 导航 | 一长串建站统计 + 5 个 tab，560px 断点仅让 stats 换行，挤压 |
| hover 交互 | 分析/趋势按钮、操作区靠 `:hover` 浮现 → **手机上不可见** |
| 页面 grid | `auto-fill minmax` 会自动单列 ✅（角色卡 160 / boss 卡 200 / 关注 240） |
| 现有 @media | 仅 4 处：nav-stats(860/560)、history-zones(480)、tl(640) |

main 版教训：线上 main 用的是 `viewport width=1200` 固定视口（桌面缩略图），即被吐槽的版本，**不要沿用**。

---

## 二、设计原则

1. **排版适配优先**：一切以 375px 不溢出为底线，统一断点 `@media (max-width: 560px)`
2. **首页收缩 + 二级弹窗**：手机端首页只保留核心信息（排行榜 = 排名/玩家/总分/三区分数条），**详细内容（角色阵容、阶级、同阶级比较、分析/趋势入口）收进二级弹窗**，点行即开——这是手机端美观的核心策略
3. **核心功能排列**：高频操作（查询、筛选、刷新、分析/趋势）在首屏一屏内可达；低频/详情操作进弹窗
4. **hover 交互失效**：所有 hover 浮现的元素手机端常显或移入弹窗
5. **触控目标 ≥40px**，列表/卡片间距 ≥8px

## 三、排版方案

统一断点：`@media (max-width: 560px)` 为主（375px 目标设备），个别组件用 480/700。

### 1. 导航（app.css）
- 导航改为**两行**：第一行 `.nav-stats`（小字，建站/访问/数据来源），第二行 `.nav-btns` 5 个 tab **等宽均分**（`flex: 1`，字号 13px，padding 缩紧）
- 560px 断点：`.nav` 允许 wrap 或改 `flex-direction: column`

### 2. 排行榜（核心，ranking.css + VirtualRankingTable.jsx + RankingRow.jsx）
**手机端采用替代排版（卡片式紧凑行），不做横滚**：

```
[1] [头像] 玩家名                    总分 121,805,184
     ID: 13215355                    ↑差值
     ┌──────────────────────────────────┐
     │ 区1 4309万   区2 2898万   区3 4972万 │  ← 三区分数条（formatScoreCompact）
     └──────────────────────────────────┘
```

- 整行可点（含三区分数条）→ 打开**二级弹窗 PlayerRankModal**（新组件）
- 行高 ROW_HEIGHT 桌面 152 → 手机 ~96；`matchMedia('(max-width: 700px)')` 动态切换列宽/行高（JS 常量联动，CSS 同步）
- 行内保留：排名（含奖牌/差值）、头像+名字+ID、总分+差值、三区分数条
- 行内隐藏（进弹窗）：角色图标列表、cub、同阶级比较标签、guild、分析/趋势按钮、zone-name
- **PlayerRankModal（新弹窗）**：顶部玩家信息（头像/名字/ID/总分+差值）→ 三个区 tab（区名+分数+差值+角色阵容列表+同阶级比较+分析/趋势按钮）→ 底部"前往玩家页"入口
  - 复用现有组件：`CharList` 样式、`TeamCompareTag`、SaModal 的分析/趋势打开逻辑
- 表头（RankingHeader）：手机端**不渲染表头**（行自带语义，无列概念），或仅渲染一行"排名/玩家/总分"极简表头
- 控制区（RankingControls）：`ranking-head` 纵向堆叠——第一行难度/周两个下拉各 `flex: 1`，第二行日期区间小字；`ranking-meta` 单行小字
- 阶级筛选（RankingHeader）：**折叠面板**——默认只显示一行"筛选 ▾"按钮，展开后 3 个下拉 + 快速按钮换行排列，字号 12px

### 3. 弹窗（modals.css + Modal.jsx）
- 560px 断点：`.modal-content` 宽度 `calc(100vw - 12px)`，圆角 12px，`max-height: 90vh` + overflow-y auto；关闭按钮 36×36（触控）
- 弹窗内表格（`.score-table`、阵容排行表、TeamModal 列表）：外层包 `overflow-x: auto` 容器（CSS 加 `.table-scroll` 类或直接对 table 容器设 overflow）
- 历史战绩三区：已有 480px 断点 1 列 ✅

### 4. 玩家查询页（pages.css）
- 搜索框 + 按钮：`flex: 1` 布局已 OK，按钮加 min-height 44px
- 角色卡 `minmax(160px, 1fr)` → 375px 天然 2 列 ✅ 无需改
- 关注/历史列表项：字号 12px，头像 32px
- 玩家信息头（头像/名字/操作按钮）：操作按钮换行

### 5. 幻痛囚笼（pages.css / PpcPage 相关）
- boss 卡 `minmax(200px, 1fr)` → 375px 单列太宽，手机断点改 `minmax(150px, 1fr)` 两列
- 榜单表格横滚容器（`overflow-x: auto`）
- 手机端 boss 卡精简：名称 + 等级 + 关键属性，详情收进已有弹窗

### 6. 我的页（pages.css）
- 表单（绑定 ID/登录）：input + button 纵向堆叠，按钮全宽
- 分数录入三区行：纵向堆叠或缩小
- `score-history` 表格横滚容器

### 7. 广告与反馈（app.css）
- `.ad-float` 宽 340px → 手机 `width: min(340px, 88vw)`
- `.corner-feedback` 字号 10px，避免遮挡内容

### 8. hover 全面检查
- `.zone-sa-btn`、`.bracket-btn`、`.clear-btn` 等所有 `:hover` 浮现/变色的元素，手机端确保**默认可见**（opacity 常显）
- 排行榜的分析/趋势按钮已收进 PlayerRankModal，不再依赖行内 hover
- 悬浮按钮可加 `:active` 反馈

## 四、技术要点

1. **列宽常量联动**：`VirtualRankingTable.jsx` 的 `COL_*` / `ROW_HEIGHT` 改为函数或 `isMobile` 分支；CSS 用相同断点覆盖。**两处必须一致**，否则表头/行错位
2. **matchMedia 监听**：`useEffect` + `mql.addEventListener('change', ...)`，旋转/横竖屏切换时更新
3. **虚拟滚动**：`rowHeight` 变化会由 List 的 prop 自动适配，但需触发 ResizeObserver 的 wrapHeight 更新（现有机制已监听）
4. **PlayerRankModal 复用**：三区 tab 内容直接复用 `SaModal` 的单区结构（角色列表/比较标签/分析趋势按钮），新增玩家头 + 三区 tab 壳即可，避免重复实现
5. 触控目标：主要按钮（查询/分析/趋势/关闭/筛选）高度 ≥40px
6. 验证手段：Playwright 375px 视口全页面回归——`document.documentElement.scrollWidth <= innerWidth`（无横向溢出；表格容器内部横滚除外，容器本身不溢出）

## 五、实现顺序

1. 全局 + 导航（app.css / theme.css）：两行导航、基础字号/间距/触控
2. 弹窗壳全屏化（modals.css）：为后续二级弹窗铺路
3. 排行榜（核心）：
   - `VirtualRankingTable`/`RankingRow` 手机模式（matchMedia 联动行高/紧凑行）
   - 新建 `PlayerRankModal`（玩家头 + 三区 tab）
   - 控制区堆叠 + 筛选折叠 + 表头隐藏
4. 玩家查询 / PPC / 我的页
5. 广告、反馈、hover 常显
6. Playwright 375px 回归（每页无溢出 + 交互可点：筛选/排序/搜索/弹窗/行点击）
